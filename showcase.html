Where and how we test the tactical intrusion-detection framework

A simulation-based test range that runs the full federated pipeline the way it would run in the field — four tactical zones detecting intrusions on their own traffic, over jamming-prone links, while the server fuses their models to catch zero-day attacks it was never trained on. Every figure below comes from an actual executed run, not a mock-up.

What we are testing, and on what

The application

A federated intrusion-detection system for tactical edge networks

Each edge node trains a local CNN classifier + autoencoder on its own network traffic and shares only model updates — never raw data — so detection works under bandwidth, privacy and connectivity limits.

The test method

Reproducible software simulation (Python / PyTorch)

There is no physical hardware testbed: the tactical network is simulated — 4 zones, a Gilbert–Elliott jammed channel, and battery/CPU models — so every run is seed-controlled and repeatable. This is the standard evaluation method for this class of research.

The data

ToN_IoT (primary) & UNSW-NB15 (transfer)

Public network-intrusion datasets. MITM, DDoS and DoS families are withheld from training and injected only at test time to measure true zero-day detection — the same protocol as the baseline paper (ZAID).

Why we fuse the autoencoder signal

Shifting weight to the autoencoder signal lifts zero-day recall (rare withheld families) at a small cost to aggregate accuracy — so the fused score, not the classifier alone, is reported.
